## 2024-05-18 - Fix ID Clashes and Screen Reader Context in Reusable Forms
**Learning:** Reusable form components that toggle inputs dynamically (like TokenSwitcher) run into two issues: 1) static `id`s clash when multiple components render, causing screen readers to misassociate labels, and 2) visual labels are sometimes omitted for aesthetics, leaving screen reader users without context for inputs like "Token Mint Address".
**Action:** Use React's `useId()` hook to generate unique `htmlFor` and `id` pairs for `<label>` and `<input>`/`<select>` pairs to ensure dynamic rendering never causes collisions. If a design omits a visual label, provide context to screen readers by adding a visually hidden `<label>` using Tailwind's `sr-only` utility class, and pair it with `useId()`. Also, use explicit `aria-label`s on icon-only buttons like "cancel".
